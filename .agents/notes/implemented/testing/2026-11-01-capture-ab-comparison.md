# Agent Note: In-memory capture A/B for wake tuning

Status: implemented

## Problem

调试“音乐下唤不醒”时，需要判断问题出在麦克风选择、回声消除还是预处理。分别跑几次现场测试不可比：音量、站位、语速和说话遍数每次都不同；只比较 RMS 也不够，AEC 曾把回声压掉 38 dB，唤醒仍然失败。把用户语音落盘再做离线回放可以解决可比性，但会保存个人录音。

## Decision

`lx06-duplex-armhf --mic-compare <秒>` 在一次采集里并行构建并打分多条候选路径：

- ch0–ch5 各自的原始降采样信号；
- 六麦平均值；
- ch0 与六麦混音分别经过 AEC、以及 AEC 加预处理的版本。合计 11 条流；当前不包含 ch1–ch5 各自的 AEC 版本。

一次采集同步构造各路径，采集结束后逐路调用相同的 `kws_measure` 检测逻辑与参数打分，并非多个检测线程实时并发。输出 `best`、`wakes`、`scored` 和均方值（`ms`，不是毫秒）；音频只留在内存，进程退出即释放，不落盘、不联网。用它把现场问题拆成两个独立测量：

- 只是放音乐、没人说话：看每条路径的 `best`，这是误唤醒的安全余量。
- 另跑一次，请用户真人说唤醒词：比较同次采集内各路径的 `best` 与 `wakes`，这是召回余量；不要与无人说话的测量混成一次。音乐、音量和站位须记录。最低距离过线不代表连续窗口确认或线上唤醒已成功。

这个工具为[音乐下唤醒失效](../bug-fix/2026-11-01-music-wake-stopped-firing.md)提供路径比较证据；符号问题还需结合动态符号与采样率日志定位，候选暂停问题还需读状态机并做线上验证。数据见[第二十二轮报告](../../reports/采集路径回声消除接入-第二十二轮.md)，正式采集边界见[采集架构笔记](../architecture/2026-11-01-speex-aec-integration.md)。

## Consequences

- 同一次运行内的路径比较是严格的：同一段音频、同一时刻、同一阈值。
- 跨运行比较只在音量与站位接近时成立；报告里必须写明当时的音量。
- 缓冲大小由代码推算为 `11 × 秒数 × 16000 × 2` 字节，20 秒约 6.7 MiB，另有 DSP 与检测器开销；不是已测 RSS。只在诊断模式下分配。
- 不能用设备扬声器回放唤醒录音验证真人召回：这段声音同时进入 ch6 播放参考，会被 AEC 作为回声抵消；真人近端语音不走播放参考。该回放可观察回声抑制，不能作为真人召回的通过或失败证据。
- 新增一个诊断入口，需要和 KWS 的阈值、`min_hits` 保持同步；改动检测器参数后旧结论需要重测。

## Alternatives considered

- **把采集存成 WAV 后离线回放**：可以反复调参而不再打扰用户，但会保存用户语音，而且需要额外的通道解析与回放代码。
- **分别部署不同版本做现场 A/B**：每次只测一条路径，环境不可控，结论不可比。
- **只比较 RMS / 抑制比**：抑制比只能说明回声被压掉，不能说明语音是否仍可识别；实际上 38 dB 抑制时唤醒依然失败。
- **直接复用 `--kws-live` 多次运行**：每次都要用户配合，且阈值、音量、站位变化无法隔离。
