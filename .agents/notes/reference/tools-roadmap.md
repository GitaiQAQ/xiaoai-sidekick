# Reference: 豆包工具接入顺序

实现方式已收敛：工具定义集中在 `src/native_tools.h`，Web 控制台通过本机 socket 的 `/api/v1/tools` 下发目录、`/api/v1/tool` 执行调用。新增一项能力＝注册表加一行＋`action_execute()` 加一个动作分支，语音端无需改动。

用户要求列举智能音箱能力并按顺序实现。2026-11-01重新直接查询实机ubus，接口清单保存logs/tools-capability-inventory.txt。存在方法不代表已验证所有参数或成功控制外设。

1. 工具调用基础与音箱状态：注册函数、解析参数、固定白名单执行、返回真实结果；先接当前音量/播放状态。
2. 音量和基础播放：设置/增减音量、暂停/继续/上一首/下一首、进度/播放模式。依据mediaplayer接口，逐项恢复原状态并验证。
3. 闹钟/倒计时/提醒：查询、创建、修改、删除，时区/重复规则/响铃回归；不提前写真实日程。alarm接口已存在，具体枚举待查。
4. 米家设备和场景：先解析现有原厂控制路径，完成设备/房间/状态，再接指定设备动作。当前miio/Mesh存在不等于可枚举和控制全部米家设备；不默认启用配网或解绑。
5. 红外家电：ir_agent存在发码/学习接口；需现有遥控器映射或后续学习，才能完成空调/电视控制。
6. 点歌/歌单/电台/播客：在基础播放之上接内容检索及原厂内容服务；网易云账户、授权/会员/播放源兼容单独验证。
7. 蓝牙/AUX/投放：连接状态、播放控制、音源切换；仅在明确目标设备和恢复方法后实测切换。
8. 夜间模式/音效：时间段、亮度/音量、音效。nightmode/sound_effect原生接口存在。
9. 天气/日历/新闻/联网查询：时间走系统，实时信息接可核实服务；不当作设备本地原生技能已接通。
10. 场景组合和体验完善：睡前定时停播、起床流程、跨工具多步骤；补小爱共存仲裁/打断/常驻/回归。

实现原则：每项按“模型声明工具→参数校验→机内执行→读取结果→模型据实回答”闭环验收，不让模型任意执行shell，不把接口退出码当设备动作成功。涉及外设先选明确设备，不批量试控家电。无开机自启变更。
