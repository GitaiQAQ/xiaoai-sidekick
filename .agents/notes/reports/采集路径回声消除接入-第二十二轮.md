# Report: 采集路径回声消除接入（第二十二轮）

## 目标

长期约束与方法记录：[采集架构](../implemented/architecture/2026-11-01-speex-aec-integration.md)、[音乐下唤醒失效修正](../implemented/bug-fix/2026-11-01-music-wake-stopped-firing.md)、[同音频采集 A/B](../implemented/testing/2026-11-01-capture-ab-comparison.md)。表中不同场景分开采集；单麦 12.05 低于诊断阈值 12.5048，但最低距离不等于连续窗口确认。

把已验证的 Speex AEC 原型接进正式采集路径，让本地唤醒和云端上行共用去回声信号，并在真实音乐下做到可以说“豆包豆包”唤醒。

## 实现

新增 `src/native_capture.h`，`native_duplex_client.c` 的所有采集读取改走这一层：

- `Capture` dsnoop 8 通道 S32/48 kHz，ch0–ch5 六个麦克风取平均，ch6 作播放参考。
- 3 点平均降采样到 16 kHz，累加器跨读取块，输出速率精确。
- 128 样本一帧跑 `speex_echo_cancellation` + `speex_preprocess_run`，采样率用 `speex_echo_ctl(st,24,&16000)` 显式设置。
- 输出环形缓冲同时供 KWS 与 agent loop 上行；调用方仍按 320 样本读取。
- 打不开 8 通道 PCM、加载不到 `libspeexdsp` 或 Speex 初始化失败时回退 `mico_record`；`--no-aec`、`LX06_AEC=0` 可强制回退。
- 音乐播放且 AEC 生效时：阈值 15.0，连续 2 个命中暂停播放器 2.2 秒做确认，未确认则恢复，6 秒冷却；静音环境仍为 12.5 / 3 连击。
- 新增 `--mic-compare <秒>` 诊断：同一段采集并行打分 ch0–ch5、6 麦混音、AEC、预处理各版本，只在内存中处理。

顺带修复 Web 控制台的 daemon 启动：读取 API key 后把 stdin 指向 `/dev/null`，否则子进程占着 SSH stdin，启动命令永不返回；`Manage-LX06Web.ps1 -Start` 补上 `SSH_ASKPASS` 环境。

## 第一轮实测：单麦、错误的采样率

设备：LX06，ROM 1.94.13，原厂 `mipns-xiaomi` PID 1282 保持运行；音乐为热歌榜队列。

- 回声抑制约 38 dB（mic RMS 52566 → 664），但真人“豆包豆包”在音乐下的最低距离只有 13–14，阈值 12.50，无法唤醒。
- 音乐下 20 秒无语音：AEC 开 0 次误唤醒，关 2 次。
- 单核 CPU 19.75% → 21.0%，RSS 2060 → 2288 kB。

## 第二轮实测：采样率修正与多麦混音

用 `--mic-compare` 对同一段真人语音并行打分（阈值 12.5048）：

| 路径 | 说话时最低距离 | 只放音乐 |
|---|---|---|
| ch0 原始 | 9.24 | 12.57 |
| ch1–ch5 原始 | 9.60–9.96 | 10.97–12.60 |
| 6 麦混音原始 | 8.97 | 11.26（误唤醒） |
| ch0 + AEC + 预处理 | 12.05 | 14.55 |
| ch0 + AEC（无预处理） | 9.57 | 14.57 |
| 6 麦混音 + AEC + 预处理 | 11.66 | 14.62（音量 30）/ 13.41（音量 34）/ 19.34（音量 17） |
| 6 麦混音 + AEC（无预处理） | 8.85 | 11.03（误唤醒） |

结论：

1. `speex_echo_state_ctl` 在本机库里不存在，实际导出的是 `speex_echo_ctl`；之前从未设置采样率。修正后 ch0 的 AEC 语音距离从 13.3 降到 9.6。
2. 预处理会把语音距离抬高约 2.5，但它是音乐残留的主要抑制手段；关掉后音乐下会误唤醒，因此保留。
3. 单麦克风在音乐下的语音距离刚好过不了阈值；改成 6 麦平均后，配合预处理可以过（11.66）。
4. 音乐残留本身随音量在 13–19 之间，和语音重叠，固定阈值无法两边都成立，因此加入“两连击候选 → 暂停音乐 → 第三窗确认”。

## 已验证与未验证

已验证：

- 音乐播放中可以唤醒，走完整会话建立与恢复播放。
- 采样率 16000 已生效（`speex_rate=16000`、`capture_speex_rate=16000`）。
- 回退开关可用；`--mic-compare` 可在不保存音频的情况下比较采集路径。
- Web 控制台重启、语音服务启动和 `/api/state` 读取正常。

未验证：

- 高音量（50 以上）与 3 米以上远场的召回率。
- 连续对话中的打断（`barge_in`）。
- 长时间运行（数小时）后的滤波器状态与误暂停频率。
- 云端上行在音乐下的转写质量。

## 复现

```powershell
# 采集路径 A/B（20 秒，说话与不说话的窗口分开跑）
& .\tools\Invoke-LX06.ps1 -Command "/lib/ld-linux-armhf.so.3 /data/lx06-agent/lx06-duplex-armhf --mic-compare 20"

# 抑制量
& .\tools\Invoke-LX06.ps1 -Command "/lib/ld-linux-armhf.so.3 /data/lx06-agent/lx06-duplex-armhf --aec-test 6"

# 待机唤醒
& .\tools\Invoke-LX06.ps1 -Command "/lib/ld-linux-armhf.so.3 /data/lx06-agent/lx06-duplex-armhf --kws 300"
```

3. 统计误暂停频率，调整 15.0 阈值、2 连击与 6 秒冷却。
4. 评估 AEC 后是否放开上行静音，做真正的语音打断。
