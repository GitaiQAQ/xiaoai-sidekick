## 1. 声音就是一串数字

### 1.1 采样

声音是空气压力的波动。麦克风把它变成电压，芯片每隔固定时间量一次电压，记成一个整数。这就叫**采样**。

- **采样率**：每秒量多少次。唤醒模型用 **16000 Hz**，也就是每秒 16000 个数。
- **位深**：每个数用几位存。我们用 **s16**（有符号 16 位整数），范围 −32768 到 32767。
- **声道**：单声道就是一串数。音箱有 8 路输入（6 个麦克风 + 回采参考），见 [audio-pipeline.md](audio-pipeline.md)。

一秒单声道 16k/s16 的音频就是 16000 个 `Int16`，32000 字节。WAV 文件就是一个小文件头加上这串数字。

前端里你见过它：Web Audio API 的 `AudioBuffer.getChannelData(0)` 返回的 `Float32Array` 就是同样的东西，只是被缩放到了 −1 到 1。

### 1.2 为什么是 16 kHz

有个定理（奈奎斯特采样定理）说：采样率是 F，最多只能表示 F/2 以下的频率。16 kHz 能表示 8 kHz 以下的声音。人说话的关键信息基本在 8 kHz 以下，所以语音识别普遍用 16 kHz；音乐 CD 用 44.1 kHz 是为了保留高音。

### 1.3 只看波形认不出字

把“小爱同学”的波形画出来，是一条上下乱跳的线。同一个人说两遍，波形就完全不同：音量、快慢、音高都会变。所以不能直接比较波形，要先把它变成更稳定的表示。第一步就是看它由哪些**频率**组成。

## 2. 傅里叶变换：把声音拆成“哪些频率、各有多响”

### 2.1 核心直觉

任何一段波形，都可以看成很多个不同频率的正弦波叠加。傅里叶变换做的就是反过来：给它一段波形，它告诉你每个频率的正弦波有多强。

打个比方：一杯混合果汁，傅里叶变换告诉你里面有多少苹果、多少橙子。

- 低频（几百 Hz）：声音的“底子”，比如男声的基频。
- 中高频（1–4 kHz）：区分元音、辅音的关键。比如 “s” 的嘶嘶声主要在高频。

### 2.2 最笨的实现（DFT），JS 版

DFT（离散傅里叶变换）的做法：对每个想检查的频率 k，拿一个该频率的正弦和余弦，和信号逐点相乘再相加。信号里含这个频率越多，乘积之和就越大。

```js
// x: 一段采样（长度 N），返回每个频率 bin 的幅度
function dft(x) {
  const N = x.length, mag = [];
  for (let k = 0; k <= N / 2; k++) {        // 只看到 N/2，超过的是镜像
    let re = 0, im = 0;
    for (let n = 0; n < N; n++) {
      const a = 2 * Math.PI * k * n / N;
      re += x[n] * Math.cos(a);
      im -= x[n] * Math.sin(a);
    }
    mag.push(Math.hypot(re, im) / (N / 2));
  }
  return mag;
}

// 造一段信号：1000 Hz（幅度 1）+ 3000 Hz（幅度 0.5）
const sr = 16000, N = 512;
const x = Array.from({ length: N }, (_, n) =>
  Math.sin(2 * Math.PI * 1000 * n / sr) + 0.5 * Math.sin(2 * Math.PI * 3000 * n / sr));

dft(x).forEach((v, k) => { if (v > 0.01) console.log(k, k * sr / N + 'Hz', v.toFixed(3)); });
```

【实测】在 Node 里跑，输出正好两行：

```text
32 1000Hz 1.000
96 3000Hz 0.500
```

两个频率、两个幅度都被准确找回来了。

几个要点：

- 第 k 个结果对应频率 `k × 采样率 / N`。N=512、16 kHz 时，每格 31.25 Hz，这叫**频率分辨率**。
- 结果只有 N/2+1 个有意义。后半部分是前半部分的镜像，因为实数信号的频谱对称。
- 这段代码是 O(N²)。**FFT（快速傅里叶变换）**是同一个数学结果的快速算法，O(N log N)。实际都用 FFT，numpy 里是 `np.fft.rfft`。

### 2.3 你其实早就用过

Web Audio API 的 `AnalyserNode` 内部就是 FFT：

```js
const analyser = audioCtx.createAnalyser();
analyser.fftSize = 512;                     // 和我们的 N 一样
const bins = new Uint8Array(analyser.frequencyBinCount); // 256 个
analyser.getByteFrequencyData(bins);        // 每个频率的响度
```

音乐播放器跳动的柱状图就是这么画的。语音识别的第一步本质上和它一样。

## 3. 短时傅里叶：给声音拍“频率快照”

### 3.1 为什么要切帧

对整段 1 秒音频做一次傅里叶变换，你只知道这一秒里有哪些频率，不知道它们出现的**顺序**。但“小爱”和“爱小”的频率成分差不多，区别全在顺序上。

解决办法：把音频切成很短的小段，每段单独做 FFT。语音在 20–30 ms 内基本稳定，所以：

- **帧长 25 ms**：16 kHz 下是 400 个采样点。
- **帧移 10 ms**：160 个点。相邻帧有重叠，就像视频每秒 100 张截图。
- 每帧补零到 512 点再做 FFT。

这样 1 秒音频就变成约 100 帧，每帧一个频谱。把它们按时间排开、用颜色表示强弱，就是**语谱图（spectrogram）**。

### 3.2 加窗：别让切口“咔哒”

直接从中间切出 400 个点，两端会突然断开。突变在频谱里会变成一堆假的高频成分（**频谱泄漏**）。解决办法是乘一个**窗函数**：中间接近 1、两头平滑降到 0，相当于给每帧做了淡入淡出。

我们本地实现用的是 Kaldi 的 povey 窗。这一步之前还有两个小处理：

- **去直流**：每帧减去自己的平均值。
- **预加重**：`y[n] = x[n] − 0.97·x[n−1]`，把高频提一提。语音高频天生弱，提一下更均衡。

【推断】这些常量来自 Kaldi 默认值。原厂设备上的确切常量还没和设备输出逐一对齐，见第 11 节。

## 4. 从频谱到 MFCC：模仿人耳

一帧 FFT 有 257 个数，太多，而且太“物理”。人耳并不是这样听声音的。MFCC（梅尔频率倒谱系数）分三步把它变成更像人耳感知、也更紧凑的 40 个数。

### 4.1 梅尔刻度：低频听得细，高频听得粗

人耳分辨 100 Hz 和 200 Hz 很容易，分辨 7000 Hz 和 7100 Hz 却很难。梅尔刻度就是把频率轴按人耳的感觉重新拉伸：

```text
mel(f) = 1127 × ln(1 + f / 700)
```

在梅尔刻度上等间隔放 **40 个三角形滤波器**：低频的三角形窄而密，高频的宽而疏。每个滤波器把它覆盖的那段频谱加权求和，得到一个数。257 个数就压成了 40 个“频带能量”。

原厂配置是 40 个滤波器、范围 20 Hz 到 7800 Hz（配置里写作 `high=-200`，表示比奈奎斯特频率 8000 Hz 低 200）。【反汇编/模型配置】

### 4.2 取对数：模仿响度感知

人对响度的感觉也是对数的：能量翻 10 倍，听起来只是“响了一档”。所以对 40 个能量取 `log`。顺带一个好处：音量整体变大，相当于每个值加了同一个常数，后面很容易减掉。

### 4.3 DCT：去掉相关性

相邻滤波器的输出高度相关（隔壁频带总是一起高、一起低）。DCT（离散余弦变换）是傅里叶变换的近亲，把这 40 个数变成 40 个彼此更独立的系数：前几个描述频谱的大轮廓（声道形状，决定是哪个元音），后面的描述细节。然后再乘一个“倒谱提升（lifter）”系数，把高阶系数放大一点，让各维度量级更接近。

**结果：每 10 ms 一个 40 维向量。** 这就是神经网络的输入。

### 4.4 CMVN：抹掉麦克风和房间的“底色”

不同麦克风、不同房间，会给所有帧加上相近的偏移。把每一维减去它在一段时间内的平均值，这个偏移就消掉了。这叫 **CMN（倒谱均值归一化）**；如果再除以标准差，就是 **CMVN**。

- 我们本地实现：整句一起算平均（离线、简单）。
- 原厂 `RiceCmvnCompute`：在线滑窗累计，边听边更新。【反汇编】
- 这是目前本地和原厂最大的已知差异之一。

## 5. 神经网络：一个由矩阵乘法串起来的纯函数

别被名字吓到。我们这个模型只用了四种运算，都可以用几十行 JS 写出来。

### 5.1 affine（全连接层）= 矩阵乘法 + 加偏置

```text
输出[o] = b[o] + Σ_i  W[o][i] × 输入[i]
```

- 输入 200 个数，输出 96 个数。W 是 96 行 × 200 列，b 是 96 个数。
- 每个输出是全部输入的加权和。**W 和 b 就是“模型学到的知识”**，也叫参数或权重。

前端类比：CSS 的 `matrix3d()` 用一个 4×4 矩阵把点坐标变成新坐标。affine 做的是同一件事，只是矩阵是 96×200，而且矩阵里的值是训练出来的，不是手写的。

### 5.2 relu = `Math.max(0, x)`

就这么简单：负数变 0，正数不变。没有它，多层矩阵乘法叠起来还是等于一个矩阵乘法，网络再深也学不到复杂规律。这种“掰弯”的函数叫**激活函数**。

### 5.3 normalize = 把向量缩放到固定长度

```text
scale = 1 / sqrt(max(Σx² × target_rms / dim, 极小值))
输出 = 输入 × scale
```

防止数值一层层越乘越大或越小。【反汇编】原厂在 0x86dcc 一带就是这个公式，`target_rms=1.0`。

### 5.4 softmax / logsoftmax = 把分数变成概率

最后一层输出 10 个任意实数。softmax 把它们变成和为 1 的概率：`p_k = e^{x_k} / Σ e^{x_j}`。logsoftmax 就是再取一次 log，后面算分时直接相加，比连乘稳定。

### 5.5 一层的完整 JS 版

```js
// x: Float32Array(inDim)，W: Float32Array(out*in) 行主序，b: Float32Array(out)
function affine(x, W, b, inDim, outDim) {
  const y = new Float32Array(outDim);
  for (let o = 0; o < outDim; o++) {
    let s = b[o];
    for (let i = 0; i < inDim; i++) s += W[o * inDim + i] * x[i];
    y[o] = s;
  }
  return y;
}
const relu = x => x.map(v => Math.max(0, v));
```

整个网络就是把这类函数按顺序串起来调用：`softmax(affine(...normalize(relu(affine(splice(x))))))`。

### 5.6 splice 与 TDNN：一次看前后好几帧

单独一帧只有 10 ms，连半个音都不到。要判断“这一帧是不是‘爱’的中间”，需要看看前后。

**splice（拼接）**就是把当前帧和前后若干帧的向量首尾拼在一起。比如偏移 `[-2,-1,0,1,2]`：把第 t−2 到 t+2 这 5 帧的 40 维拼起来，变成 200 维。这就是上面 affine 输入是 200 的原因。

**TDNN（时延神经网络）**就是在不同层用不同的 splice。原厂模型三次拼接：

| 位置 | 偏移 | 含义 |
|---|---|---|
| 第 1 次 | `[-2..2]` | 看前后 20 ms，抓音素细节 |
| 第 2 次 | `[-6,-3,0,3]` | 跨度更大，抓音素之间的过渡 |
| 第 3 次 | `[-32,-23,-14,-5,4]` | 往回看 320 ms，抓整个字甚至两个字 |

三次偏移累计，最左看 2+6+32 = **40 帧**，最右看 2+3+4 = **9 帧**。【实测】模型开头的 padding 组件正好是左 40、右 9：在首尾各复制几帧，让输出帧数等于输入帧数。往右只看 9 帧（90 ms），所以判醒延迟很小，适合实时。

### 5.7 原厂模型长什么样【实测】

```text
input(40 维)
 > padding(左40,右9)
 > splice[-2..2] 40→200 > affine 200→D > relu > normalize
 > (affine D→D > relu > normalize) ×2
 > splice[-6,-3,0,3] → affine 4D→D > relu > normalize > (affine D→D > relu > normalize) ×2
 > splice[-32,-23,-14,-5,4] → affine 5D→D > relu > normalize > (affine D→D > relu > normalize) ×2
 > affine D→10 > logsoftmax
```

| | 一级 | 二级 |
|---|---|---|
| 隐层宽度 D | 96 | 160 |
| 参数量 | 159274 | 419050 |
| 文件大小 | 约 0.6 MB | 约 1.7 MB |

一级参数量可以手算验证：

```text
200×96+96          =  19296   第一层
(96×96+96)×6       =  55872   六个 D→D 层
384×96+96          =  36960   第二次拼接后
480×96+96          =  46176   第三次拼接后
96×10+10           =    970   输出层
合计               = 159274
```

作为对比，一个现代大语言模型有几十亿到上千亿参数。这个唤醒模型小到能在音箱的 CPU 上每 10 ms 跑一次。

## 6. 网络输出的 10 个数是什么

### 6.1 音素和 pdf

语音识别不直接认“字”，而是认更小的单位：**音素**（phone），大致对应拼音里的声母、韵母。“小爱同学” ≈ x-iao-ai-t-ong-x-ue。

原厂模型只关心一个词，所以只需要很少的类别：**10 个 pdf**（输出类别）。【实测/模型文件】TransitionModel 里 10 个 phone 各有 1 个状态，pdf = phone − 1。

【推断】大致分工：

- pdf 0：最常见（先验最大），很可能是静音。
- pdf 3：垃圾（“不是关键词的任何声音”）的主力。
- 其余 8 个类别依次对应“小爱同学”里的 8 个音素位置。其中一个音素出现两次，和“小”“学”都以 x 开头吻合。

每一帧，网络输出这 10 类的对数概率，叫**后验**：“看了这一帧（及前后），它属于类别 k 的可能性”。

### 6.2 先验（prior）和声学分

训练数据里静音特别多，网络会天然偏向输出“静音”。为了纠正这种偏见，把后验除以该类别在训练数据中出现的频率（**先验**），在对数域就是相减：

```text
声学分[t][k] = 0.1 × (log 后验[t][k] − log 先验[k])
```

0.1 是 acoustic-scale，【实测】原厂两级都是 0.1。一级的 10 个 log 先验约为：

```text
[-0.45, -4.71, -4.48, -1.36, -4.84, -4.25, -4.72, -3.55, -4.36, -4.62]
```

pdf 0（-0.45）和 pdf 3（-1.36）明显最大，符合“静音和垃圾最多”的推断。

### 6.3 一个直观的例子【实测】

把每帧概率最大的类别取出来，再合并连续重复，用 macOS 合成的语音测一级模型：

```text
“小爱同学”  [0, 3, 1, 3, 1, 3, 1, 3, 2, 3, 2, 3, 2, 3, 2, 3, 6, 5, 3, 5, 9, 3, 9, 3, 7, 3, 0]
“豆包豆包”  [0, 3, 0]
```

“小爱同学”让网络在多个“关键词类别”之间来回走；“豆包豆包”从头到尾都只是静音和垃圾。也就是说：**这个模型根本没学过“豆包豆包”，它听到的只是一段“别的声音”。** 这就是为什么不能靠改阈值或改标签让原厂模型认豆包，必须训练自己的权重。

## 7. 状态机与 Viterbi：把“每帧的猜测”连成一个词

### 7.1 为什么还需要一步

每帧的猜测会抖动，而且“小爱同学”的每个音持续时间不同（有人说得快，有人拖长）。我们需要回答的是：**有没有一段连续的帧，按顺序依次经过了“小-爱-同-学”的 8 个音？**

### 7.2 FST：一个带权重的状态机

前端类比：XState 状态机，或者一张路由表。原厂的识别图（FST）有 10 个状态、19 条边【实测】：

```text
            垃圾/静音
  ┌─────► [1] ──┐
  │             │ (回到 0)
[0] ◄───────────┘
  │
  └─ 音1 ─► [2] ─ 音2 ─► [3] ─ 音3 ─► ... ─ 音8 ─► [9] 关键词结束
         ↺自环        ↺自环
```

- 从起点 0 有两类出口：走垃圾/静音（去状态 1，再回 0），或进入关键词的第一个音。
- 关键词路径上每个状态有一条**自环**（这个音还没说完，下一帧继续停留）和一条**前进边**（进入下一个音）。
- 每条边有代价：自环 1.0，前进 2.25（二级是 4.0）。边上还标着它“消耗”哪个 pdf。

### 7.3 Viterbi：动态规划找最短路径

每来一帧，对每个状态记录“走到这里的最低代价”：

```text
新代价[下一状态] = min over 所有进入它的边 ( 旧代价[来源状态] + 边代价 − 这一帧在该边 pdf 上的声学分 )
```

声学分越高（越像这个音），代价越低。这和前端里算“最长公共子序列”或编辑距离的 DP 表格是同一类算法。

最后比较两个数：

- 走完整个关键词到状态 9 的代价；
- 一直待在垃圾/静音的代价。

前者明显更低，就说明这段音频更像关键词。我们本地工具输出的 `margin = 关键词代价 − 垃圾代价`，**负数代表关键词路径胜出**。注意这是我们自己定的对照指标，不是原厂的 score。

【实测】一级模型、macOS 合成语音的部分结果：

| 样本 | margin |
|---|---:|
| 小爱同学 | −12.69 |
| 小白同学 | 3.44 |
| 你好小爱 | 12.85 |
| 豆包豆包 | 17.25 |

## 8. 两级判醒：先粗筛、再复核

原厂同时带两个结构相同、大小不同的模型：

- **一级**（D=96）：便宜，常驻每 10 ms 跑，宁可多报，也不能漏。
- **二级**（D=160）：一级报了候选后，对缓存的同一段音频再算一遍，严格把关。

这就像前端表单：输入框失焦时做轻量校验，提交时后端再严格校验一次。

【实测】第二十四轮在音箱上用合成的“小爱同学”测试：一级给出候选（score 8.11），二级没有确认。本轮 macOS 参考推理里，二级模型也拒绝了全部合成语音。合成语音和真人录音差别不小，这是我们强调需要真人录音的原因之一。

## 9. 模型文件格式：我们逆向出了什么

### 9.1 容器套娃

原厂模型被编译进了 `libxaudio_engine.so`。外层是一个容器（BINN 风格的键值结构），里面有 5 个部件：

| 部件 | 内容 |
|---|---|
| conf | MFCC 参数（40 维、40 个滤波器、16 kHz…） |
| model | TransitionModel：phone/状态/pdf 的对应关系 |
| fst | 第 7 节的状态机 |
| am | 声学模型，即第 5 节的神经网络 |
| prior | 第 6 节的先验 |

本轮的新进展是把 **am** 的二进制格式完整还原了。

### 9.2 am 的格式：一串 32 位整数和浮点数

格式很朴素，就是依次排列的 4 字节小端整数或浮点数：

```text
组件数
对每个组件：
  类型码
  该类型自己的字段（例如 affine：in, out, W[out×in], b[out]）
  输入个数, 输入组件编号...      （input 类型没有这一项）
```

类型码表是从原厂的“名字→编号”函数里读出来的【反汇编】，例如 6=splice、7=padding、8=affine、9=relu、17=normalize、19=softmax。

用前端熟悉的 `DataView` 就能读，下面这段 Node 代码直接解析原厂文件开头：

```js
import fs from 'node:fs';
const buf = fs.readFileSync('temp/analysis/models/mdata_wakeup_mobile/root.list.3.am.bin');
const dv = new DataView(buf.buffer, buf.byteOffset, buf.byteLength);
let p = 0;
const i32 = () => { const v = dv.getInt32(p, true); p += 4; return v; };
const f32 = () => { const v = dv.getFloat32(p, true); p += 4; return v; };

console.log('组件数', i32());
console.log('#0 类型', i32());                                        // 1 = input
console.log('#1 类型', i32(), '字段', [i32(), i32(), i32(), i32()], '输入', i32(), i32());
const t = i32(), f = [i32(), i32(), i32(), i32(), i32(), i32(), i32()], has = i32();
const n = i32(), f44 = i32(), offs = Array.from({ length: n }, i32);
console.log('#2 类型', t, 'in/out', f[0], f[1], '偏移', offs, '输入', i32(), i32());
const t3 = i32(), inn = i32(), out = i32();
console.log('#3 类型', t3, `W 是 ${out}×${inn}`, '前 3 个权重', [f32(), f32(), f32()].map(x => x.toFixed(4)));
```

【实测】输出：

```text
组件数 34
#0 类型 1
#1 类型 7 字段 [ 40, 9, 1, 1 ] 输入 1 0
#2 类型 6 in/out 40 200 偏移 [ -2, -1, 0, 1, 2 ] 输入 1 1
#3 类型 8 W 是 96×200 前 3 个权重 [ '-0.1837', '-0.0686', '-0.0708' ]
```

和第 5 节描述的结构一一对应：34 个组件，padding 左 40 右 9，第一次 splice 把 40 维拼成 200 维，第一层 affine 是 96×200。

### 9.3 怎么确认理解是对的

两道检查：

1. **逐字节往返**【实测】：`tools/native-model-am.py` 先把文件解析成结构，再按我们理解的格式写回去，结果与原文件一字节都不差，并且没有多余或缺少的字节。
2. **数值合理性**【实测】：用解析出的权重在 macOS 上跑第 6、7 节的计算，合成的“小爱同学”能走通关键词路径，相近词被拒绝。如果把 W 的行列理解反了，结果会变得毫无意义。

往返一致只能说明“格式读写对了”，不能说明原厂程序会接受我们新写的文件。后者要在音箱上用隔离程序验证。

## 10. 怎么让原厂引擎用我们的模型

【反汇编】原厂引擎有两层：

- 外层 `Paddy`：生产进程调用的接口。初始化时会把“自定义模型指针”（引擎状态结构里偏移 0x68 的字段）清零，所以永远使用内置模型。
- 内层 `RiceEngineInit`：导出函数。它检查这个指针，**如果不为空，就直接解析调用方提供的模型**，否则才拷贝内置模型。

前端类比：一个库的公开 API 永远用默认配置，但底层函数其实接受 `options.model`，只是公开 API 把它重置成了 `undefined`。我们绕过公开 API，自己调用底层函数并传入 `options.model`。

计划是写一个独立的小程序，在音箱的 `/tmp` 里运行：自己准备状态结构，填入我们的模型，再调用原厂的初始化和识别函数。它不碰正在运行的生产进程，也不写持久存储。【推断】可行，尚未上机验证。

## 11. 为什么还要上机取“标准答案”

本地 macOS 实现和原厂实现之间还有已知差异【反汇编/推断】：

- CMVN：原厂是在线滑窗，本地是整句平均。
- 原厂特征初始化里可能有随机抖动（dither）。
- 窗函数、提升系数等常量还没逐一核对。
- 原厂最终怎么算 score、怎么用阈值，还没在本地复刻。

如果特征有偏差，在 macOS 上训练出的模型装进音箱后效果会走样。所以下一步要在音箱上把原厂模型原样喂给隔离程序，对同一批音频记录原厂的输出，作为本地实现的“标准答案”（golden reference），把本地实现对齐到数字一致。

## 12. 训练自己的“豆包豆包”模型

格式和加载都打通后，剩下的是“教网络认豆包”。

### 12.1 要训练什么

- **结构**：沿用原厂结构（同样的 TDNN，可以先用一级 D=96 的规模），这样原厂引擎能直接加载。
- **类别**：重新设计。“豆包豆包”≈ d-ou-b-ao-d-ou-b-ao，再加静音和垃圾类。识别图（FST）、TransitionModel 和先验都按新的类别数重新生成。
- **权重**：从零训练。原厂权重学的是“小爱同学”的声音，不能直接复用。

### 12.2 训练是怎么回事

对前端来说，可以这样理解：

1. 网络是一个带有大量可调旋钮（W 和 b）的函数。
2. 给它一帧特征，同时告诉它正确答案（这一帧是“d”还是“ou”，还是静音）。
3. 用**交叉熵**衡量“它给正确答案的概率有多低”，越低越要惩罚。
4. 用**梯度下降**把所有旋钮朝“减少惩罚”的方向微调一点点。
5. 对几十万帧重复几万次。

“每一帧的正确答案”从哪来？我们只知道整段录音说的是“豆包豆包”，不知道哪一帧是“d”。这需要**强制对齐**：先用一个粗糙模型或现成工具，把已知文本按顺序对到时间轴上，得到逐帧标签。

工具上可以用 PyTorch 在 Mac 上训练，模型很小，CPU 就够；训练完把权重用我们的写出器写成原厂格式。

### 12.3 数据决定一切

| 数据 | 作用 | 来源 |
|---|---|---|
| 真人“豆包豆包”正例 | 模型要认的东西 | 用户录音，最好经过音箱的回声消除链路 |
| 合成语音正例 | 增加说话人、语速、音调多样性 | 多个 TTS 引擎批量合成 |
| 相近词负例 | “豆豆”“宝宝”“豆腐豆腐”等，防误唤醒 | 合成 + 真人 |
| 普通说话、音乐 | 让模型学会“这些都是垃圾” | 合成、公开语料、音箱现场录音 |

为什么合成语音不能完全替代真人：TTS 的发音太“标准”，缺少真实口音、房间混响、离麦克风远近、音乐背景下的回声残留。第二十三轮里，PC 上的现成唤醒模型能检出合成语音，却检不出已有的真人录音，就是这个问题的实例。

另外，**音乐负例**直接针对当前要修的故障。现在的唤醒方案（MFCC + DTW 模板匹配，见 [kws.md](kws.md)）只会比较“和几段模板录音像不像”，没学过“音乐长什么样”，所以会把音乐当成唤醒词。神经网络模型可以在训练时专门看大量音乐，学会把它判为垃圾。

### 12.4 验收顺序

1. macOS：正例召回率、相近词和音乐的误唤醒率，用模型没见过的录音测。
2. 音箱隔离程序：同样的音频在原厂引擎里复测，结果应和 macOS 一致。
3. 现场测试：分开做“无人说话只放音乐”和“真人呼叫”两组，记录音量、距离、时长。
4. 全部通过后，再制定接入生产和回滚方案。

## 14. 名词速查

| 名词 | 一句话解释 |
|---|---|
| 采样率 | 每秒记录多少个数，唤醒用 16000 |
| s16 / PCM | 每个采样是一个 16 位整数；未压缩的原始音频 |
| 傅里叶变换 / DFT / FFT | 把波形拆成各频率的强度；FFT 是快速算法 |
| 帧 / 帧移 | 25 ms 一小段，每 10 ms 取一段 |
| 窗函数 | 每帧两端淡入淡出，避免假高频 |
| 梅尔刻度 | 按人耳感觉重新划分频率轴 |
| MFCC | 每帧 40 个数的语音“指纹” |
| CMVN | 减去平均值，抹掉麦克风和房间的固定偏差 |
| affine | 矩阵乘法加偏置，模型的主要参数所在 |
| relu | `max(0, x)` |
| softmax | 把分数变成和为 1 的概率 |
| splice / TDNN | 把前后帧拼起来；多层拼接看更长的上下文 |
| 参数 / 权重 | W 和 b，训练出来的数字 |
| 音素 / phone | 比字更小的发音单位 |
| pdf | 网络的输出类别，这里有 10 个 |
| 后验 / 先验 | 网络对这一帧的判断 / 各类别本来有多常见 |
| FST | 带权重的状态机，规定词里音素的顺序 |
| Viterbi | 动态规划，找代价最低的状态路径 |
| 一级 / 二级 | 小模型粗筛、大模型复核 |
| 强制对齐 | 已知文本时，推算每帧对应哪个音素 |
| 交叉熵 / 梯度下降 | 训练时衡量错误 / 调整参数的方法 |
| AEC | 回声消除：从麦克风信号里减掉音箱自己放的声音 |
| DTW | 现在线上用的模板匹配方法，按时间伸缩比较两段特征 |
| golden reference | 在音箱上用原厂实现跑出的标准答案 |
